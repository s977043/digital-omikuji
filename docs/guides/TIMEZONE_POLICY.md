# タイムゾーン戦略

おみくじ本体の「1 日 1 回制限」判定におけるタイムゾーンの扱いを明文化する。

## 概要

Digital Omikuji は **デバイスのローカルタイムゾーン** を基準に「今日」を判定する。
ユーザーが最後に引いた日付（`omikuji_last_draw_date`）とローカル日付の比較で再引きの可否を決定し、外部サーバーや UTC を使わない。

## 実装

- 判定ロジック: `domain/fortuneRules.ts` の `getTodayString()` / `canDrawToday()`
- 返却形式: `YYYY-MM-DD`（例: `2026-01-01`）
- 比較対象: `AsyncStorage` に保存された前回の引き取り日付キー `omikuji_last_draw_date`（`utils/HistoryStorage.ts` が読み書き）

## 設計理由

- **外部送信なしポリシー**: サーバーや外部 API に頼らずに日付判定を行う
- **プライバシー重視**: 位置情報やアカウント情報を要求しない
- **シンプルさ**: OS の `Date` API のみで完結し、追加依存を発生させない

## 既知の挙動

### 想定内

| ケース                                  | 挙動                                                                                           |
| --------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 同一デバイスで日付が変わる（深夜 0 時） | ローカル日付が変わった時点で再引き可能                                                         |
| OS の日時を手動で翌日に進める           | 再引き可能（意図的に許容）                                                                     |
| OS の日時を手動で前日に戻す             | 同日扱い → 再引き不可（`last_draw_date > today` の辞書順比較は行わず、単純な文字列一致で判定） |

### 国境越え・タイムゾーン変更時

| ケース                                                              | 挙動                                                             |
| ------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 東京 23:30 に引き、直後に飛行機で UTC-10 へ移動しタイムゾーンを切替 | 現地時刻で日付が進んでいれば再引き可能、戻っていれば不可         |
| 端末のタイムゾーンを手動で進める                                    | ローカル日付基準で判定されるため、日付が変わっていれば再引き可能 |

この挙動は仕様通り（ローカル基準）であり、バグではない。

## 将来 UTC 切替する場合の移行方針

サーバー送信や海外滞在時の厳密な「1 日 1 回」を重視する要件が生じた場合、以下の手順で UTC 基準に切り替え可能。

1. `getTodayString()` を `toISOString().slice(0, 10)` ベースに変更
2. AsyncStorage キーを `omikuji_last_draw_date` → `omikuji_last_draw_date_utc` に変更
3. 旧キーを読み、ローカル日付として解釈したうえで UTC 換算した日付を新キーに書き込むマイグレーションを初回起動時に実施
4. 旧キーは次メジャーバージョンまで保持し、その後削除

UTC 化は仕様変更であり、リリースノートとユーザー向け FAQ の更新が必須。
