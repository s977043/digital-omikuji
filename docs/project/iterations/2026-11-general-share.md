# 一般向けおみくじの共有文修正

基準: develop `410c860e76d56dcfbc0a7347fdd179cd666a568c`。専用worktreeで作業し、既存PR #468とDependabotのブランチは変更しない。

## 観測 → 改善 → 独立レビュー

観測者は実装担当とは別のエージェント。基準コミットの純粋関数を日英の結果で実行し、英語の結果にも日本語の「2026年のエンジニア運勢は」が付くことを再現した。共有の外枠とハッシュタグがdomainで固定され、既存の翻訳 `fortune.shareMessage` が使われていなかった。実ユーザーの声は今回の「エンジニア運勢はバグ」という指摘のみで、追加募集・架空の評価はない。

改善者は `getFortuneText` と同じ翻訳関数注入を採用。既存日英テンプレートを正本にし、表示中の運勢名・説明をそのまま補間する。職業・2026年・令和八年の固定を除き、共有URLのcampaignも `omikuji` に整合させる。公開URL、抽選、履歴、画像処理、Android分岐は変更しない。ホームの新春表現・年の表記変更は今回の共有文修正に含めない。

- 日本語: `私の運勢は… ✨ {表示された運勢} ✨`、`#デジタルおみくじ #おみくじ`。
- 英語: `My fortune is… ✨ {displayed fortune} ✨`、`#DigitalOmikuji #Omikuji`。
- URLのUTM campaign変更で過去の `omikuji2026` と集計が分かれる。年を偽って共有しないための意図した変更。

独立レビュアーは最小差分・結果保持・言語・Android境界・E2E方針を確認し、阻害指摘なし。提案されたDOMAIN_LAYERの関数引数説明も更新した。

最初の新domainテストは旧実装で2件失敗。ただし新引数形式のテストなので、バグそのものの再現根拠は観測者が旧APIで行った実行と区別する。修正後の日英テストは成功。pnpm testへのrunInBand引数の指定が拒否されたため、pnpm exec jest --runInBandで全テストを実行し成功した。

Web E2Eは実際の共有先を開かずnavigator.shareの引数のみ捕捉する。AndroidはモックによるJS API境界の確認であり、実機/OS共有シート/共有先アプリでの表示は未検証。Web非対応ブラウザーは従来どおりPNGダウンロードで、テキスト共有の新しいfallbackは追加しない。新規依存・共通E2E基盤・AAT編集・外部投稿・課金なし。Plugin実行は利用不可でCLI代用なし。

今回の学び: 翻訳済みの結果と共有の外枠を同じ言語で組み立て、テンプレート単体だけでなく実画面→共有API境界まで検証する。AAT/記事向け候補として記録し、外部公開は行わない。
