## フローと受入条件

起動 → 回数・再表示・操作方法を読む → 引く → 結果 → 持ち帰る → 再起動 → 同じ結果を再表示。

- 初回の抽選前に 1 日 1 回と当日結果の再表示を案内する。
- Web / シェイク無効設定ではタップのみを案内する。ネイティブの有効設定では両方を案内する。
- CTA の accessibilityHint も表示案内と一致する。
- 当日の結果全文と保存済み履歴が再読込後も変わらず、新たな抽選を誘導しない。
- 新しい依存、課金、計測 SDK、共通 E2E 基盤を追加しない。

## 検証・5 ループ

1. 要件: 監査・Issue・既存 PR と照合。新規 E2E は変更前に案内欠落で失敗することを確認した。
2. 境界: Web / Android × シェイク設定有無の 4 ケースと画面から設定を渡す統合テストを追加。
3. 設計・安全: 既存 Pattern と i18n のみ変更。保存形式・日付判定・センサー・依存更新なし。実装と別の Codex がレビュー。
4. 回帰・統合: 型検査 / ESLint 成功、Jest 45 suites / 316 tests 成功、Web export 6 routes 成功。既存の export 終了警告は継続。
5. 最終条件: 実画面の 390 / 320px を比較。Web E2E は初回→抽選→保存→reload→同結果と既存ルートを検証。結果全文・履歴一致を独立レビューで強化した。ローカル Chromium の 6 件が成功。CI は PR に記録する。

E2E の初回比較失敗は innerText を textContent と比較したテスト側の相違。
`useInnerText` で同じ取得方法に揃え、結果全文と生の保存データを比較する。
Web テストは Android 実機の検証ではない。シェイク設定を変更して即戻った場合の native hook 同期、TalkBack、文字拡大、センサー、共有、AAB、ストア申請は未検証。
既存 SDK 不整合による expo-doctor 失敗は別問題で、依存をこの変更で更新しない。
